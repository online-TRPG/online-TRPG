# UX 개선 검증 증거

이 문서는 `doc/user_experience_remediation_plan.md` 구현 결과를 검증할 때 사용하는 기록지다. 코드 작성만으로 완료 처리하지 않으며, 실제 실행 결과가 생길 때마다 아래 상태와 증거를 갱신한다.

## 기록 원칙

- 상태는 `미실행`, `통과`, `실패`, `차단` 중 하나만 사용한다.
- 실패 시 화면 캡처, API error code, 재현 계정 역할, 세션 활동 상태를 기록한다.
- 채팅·행동·AI 프롬프트 원문, 이메일, access token, 내부 사용자 ID는 기록하지 않는다.
- 스크린샷에 민감한 본문이 있으면 첨부 전에 가린다.

## 자동 검증

| 범위 | 명령 | 현재 상태 | 결과/증거 |
|---|---|---|---|
| 정적 사용자 식별자 | `npm run verify:user-facing-identifiers` | 미실행 | 사용자 실행 필요 |
| 공유 타입 | `npm run build -w @trpg/shared-types` | 미실행 | 사용자 실행 필요 |
| 백엔드 단위/회귀 | `npm run test -w @trpg/be` | 미실행 | 사용자 실행 필요 |
| 프론트 단위·axe | `npm run test -w @trpg/fe` | 미실행 | 사용자 실행 필요 |
| 프론트 빌드 | `npm run build -w @trpg/fe` | 미실행 | 사용자 실행 필요 |
| 데스크톱 접근성 smoke | `npm run test:ux-e2e` | 미실행 | FE/BE 실행 후 사용자 실행 필요 |

| 최초 방문 튜토리얼 | 새 게스트 | 7일 보존 안내 → 튜토리얼 → 첫 행동 | 미실행 | 사용자 검증 필요 |

| 초대 참가 | 일반 회원 / 초대 링크 | 미리보기, 근접 경고, 참가 완료 | 미실행 | 사용자 검증 필요 |
| 플레이 일정 운영 | 세션 관리자 / 대기 중 세션 | 일정 예약·자동/수동 개방, 일정 없이 즉시 개방, 시작 전 대기실 닫기, 플레이 시작 → 진행 저장 후 닫기 | 미실행 | 사용자 검증 필요 |
| 단일 실시간 플레이 | 두 개의 열린 플레이 참가자 | 전환 확인, 기존 소켓 해제, 새 플레이 입장 | 미실행 | 사용자 검증 필요 |
| 사람 GM 진행 | 사람 GM / 구조화 시나리오 | 묘사·NPC 발화·장면 이동·자료 공개·전투 시작 | 미실행 | 사용자 검증 필요 |
| 시나리오 공개 | 제작자 / 3장면 초안 | 내부 ID 미노출, 오류 위치 이동, 공개 취소 시 초안 보존 | 미실행 | 사용자 검증 필요 |
| 비밀번호 변경 | LOCAL 회원 | 현재 비밀번호 확인, 변경 후 재로그인 | 미실행 | 사용자 검증 필요 |

| OAuth/게스트 탈퇴 | KAKAO·DISCORD·GUEST | 제공자별 재인증/최종 확인 | 미실행 | 사용자 검증 필요 |
| 키보드 플레이 | 일반 회원 / 데스크톱 | 공개 세션 탐색부터 첫 행동, 드래그 없는 토큰 이동 | 미실행 | 사용자 검증 필요 |
| 200% 확대 | 일반 회원 / 1440×900 데스크톱 | 로그인부터 첫 행동까지 문구·조작 유지 | 미실행 | 사용자 검증 필요 |

## 외부 구성 상태

- 비밀번호 재설정 메일은 `PASSWORD_RESET_EMAIL_WEBHOOK_URL`이 설정되어야 실제 발송된다.
- 발송 provider가 정해지고 운영 환경에서 성공 증거가 남기 전에는 공개 가입의 계정 복구를 완료로 판정하지 않는다.
- 제품 이벤트는 외부 분석 도구 없이 서버의 `ProductEvent` 구조화 로그에 기록한다. 이벤트 DTO는 원문 행동·채팅·프롬프트 필드를 허용하지 않는다.
